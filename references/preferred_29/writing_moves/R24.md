**摘要动作顺序。** 高层语义需要与板载算力的冲突 → USS-Nav 统一表示 → polyhedral expansion 编码几何拓扑 → 拓扑聚类产生区域 → 并行对象语义锚到拓扑 → 依托层级的 LLM 全局选区/局部信息增益覆盖 → 资源平台更新率与导航消融证据 → 代码可用性承诺。这篇偏体系摘要，优点是结构生成的产物正好成为下一阶段决策对象。

**Introduction 段落链。** 无人机语义探索的自然语言例子使任务可理解；地面/模拟系统丰沛资源与 UAV 的 SWaP 差异缩小问题范围；明确两个挑战：统一空间语义表示和计算负担（p1 b8）；按表示类型比较占据图、场景图、语义值图/VLN，各说缺少何种信息、哪些计算会变重（p2 b0）；对应给拓扑、区域、对象和 coarse coverage 的轻量构建；引出层级探索及评估，四条贡献对应表示构建、对象层、决策、部署（p2 b0–b4）。它不是“图结构很好”的泛论，而是逐项对照信息缺失和计算负担。

**篇章 / 引用 / 公式观察。** 极短 Overview → Scene Graph 三层构建 → Hierarchical Exploration → Experiments。p3 b5 引用空间骨架 [21] 后立即指出原法 global batch 不适合局部 grid 增量，继而提出新生长方式。p4 b6–b8 不为标准 modularity 再铺长公式，而说明图边类型、weak-link 权重和 Leiden [22] 的用途，再解释全局重聚类的 ID 不一致为何要求局部更新。p5 b3–b12 才为真正要实现的 object association 定义几何匹配 Eq. (1)、语义 cosine Eq. (2) 和判定优先级。公式多少由需要辨明的运算决定，不能把全篇公式数当硬指标。

**为什么像研究论证。** p5 b0–b1 用新节点、受影响邻区和不相交区域三个对象解释为何局部更新保持外区不变，是方法性质说明。p7 b2–b3 比较没有层级决策的版本，先说简单拓扑任务表现相近，再解释复杂长程任务缺少全局语义导致无效探索；机制价值有任务条件，不能改写成所有场景都全面领先。也须防止照抄来源瑕疵：p3 b4 仍有 Fig. x 占位；p6 b8 明示 LLM 是唯一外部服务，因此不能把“轻量板载系统”改写成所有计算完全板载。
