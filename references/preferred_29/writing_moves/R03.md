**摘要动作序列（p1 b3）**：人类驾驶能高速、完全自主仍困难 → 将方法限定在已有 MINCO 框架 → 球形空间表示 → 两项新前端设计分别是什么 → 两者共同扩大当前状态可用的走廊自由 → 仿真 benchmark → 消融检验两设计必要性 → 无先验地图、无外部定位的真实高速飞行及实际速度。来源骨干、新贡献和验证环境分得很清楚。

**引言逻辑链（p1 b5、b21–b22；p2 b0）**：高速未知环境及载荷/传感限制 → 重规划时新障碍要求急剧机动 → 已有前后端范式 → 前端给的空间可能太小，以致后端根本没有动态可行解 → 后端还须高效做时空变形 → 直接承认后端采用已有 MINCO，贡献集中前端 → 分别解释大重叠球空间与上一周期走廊复用为什么解决高速可行性 → 集成、消融与实飞贡献收束。

**篇章观察**：Preliminaries 先解释已有后端和走廊优化，再由 Planner 讲真正新前端，最后 Experiments；这比“所有数学全放 Method”更诚实且可读（p3 b1、p4 b1、p6 b5）。

**引用观察**：引言 [8] 明确承担 MINCO 来源；算法方法 [16,17] 被精确比较为只考虑球间连通，因而不足以保留大机动空间（p4 b12）。实验说明 [7] 的原仿真环境不可得、按描述复现，并披露基线数值从 [7] 获取（p6 b5–b8）。来源与复现边界是论证的一部分。

**公式观察**：球半径 Eq.(6) 紧随实体定义，并立即说明轨迹每段被约束于相应球中；解释单球体积和两球交集分别给什么自由后，再写 Score Eq.(7)（p4 b2–b4、b26、b35–b36）。它不是凭空给两个权重再把含义留到表格。

**像论证而非说明书的一处**：消融段明确说只改 frontend 与共同 MINCO 时成功率接近；RHC 才先产生明显提升，完整 frontend+RHC 再得到更高成功率（p6 b10）。这保留条件与交互，而非把每个子模块都写成单独显著提升。
