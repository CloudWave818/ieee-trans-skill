# 用范文学习论证与叙述

用于摘要、Introduction、方法、结果、全稿风格修订，以及用户指出“像说明书”的任务。先读取 [writing_moves/INDEX.md](writing_moves/INDEX.md) 中所选主范本的写作卡，再回到卡中指定的原文页。逐篇卡记录摘要/引言的实际推进和方法/结果的抽样观察；不是29篇都遵循的一套句子模板。逐句的主语、谓语、条件范围、信息次序与数字表达使用 [SENTENCE_CRAFT_PLAYBOOK.md](SENTENCE_CRAFT_PLAYBOOK.md) 和卡内微观单元，与段落论证一起修订。

## 1. 先判断缺的是论证还是措辞

现有稿件指纹提供章节树、文本占比和少量段落样本，不能单独说明一段正文为什么读起来成立。旧知识文件中的公式数量、消融频率和泛化比例，也不是句段写法的证据。使用这些统计作预算参照时，另选真实段落检查理由、条件、证据和推论。

先诊断实际文字：

- **清单代替解释**：连续报告用了什么模块、跑了什么试验，却未解释某一步回答了哪个未决问题。
- **名词代替机制**：用完整、统一、高效等形容词概括作用，没有说明量、接口、约束或信息怎样改变。
- **公式断开**：先给符号表和多条式子，读者要自己猜每一条为何需要、如何导向下一步。
- **文献堆叠**：按作者逐一介绍，或用一组引用支撑几种不同的局限，尚未建立有条件的比较。
- **结论重播**：摘要、引言末段、贡献、结果和结论反复播放同一套模块和验证项目。

有些段落本就应描述步骤、训练设置或设备，真实范文也使用列表。保留复现必需的细节；缺少问题、理由或结果解释的段落，才需要重新组织。不能仅凭连接词、句长或第一人称判断写作质量。

## 2. 从原文读出可迁移的依存关系

对所选来源记录简短的 `source page → observed moves → project facts → preserved/changed relation`，放在工作笔记中。正文保持论文叙述，不写入生产门禁、内部审计状态和这张映射表。

除句子或段落职责外，还要写明：

1. 前一句留下了什么问题、对象或限制？
2. 下一句通过补条件、作比较、给机制、引入定义、报告证据或收窄结论，怎样推进它？
3. 哪一关系由新项目支持，哪一关系在新项目中不存在，需要改变？

语言节奏服从推理负担。可用长句连接紧密的条件与结果，也可用短句明确判断；保持技术名词稳定，不用同义词轮换制造“人味”。不要固定每段句数或给每段复制同一收尾句。

## 3. 摘要先让读者明白论文回答了什么

所选范本决定从场景、矛盾、科学问题、计算瓶颈还是主要发现进入；随后沿它实际使用的顺序推进。记录句子级动作及依存，不预设五句、三模块、最后必须加数字等配额。

- 把核心问题具体化到对象与条件，避免用领域重要性替代问题。
- 方法说明优先交代解决问题的关键机制及理由；模块名只保留理解机制所需的部分。
- 报告最有解释力的已证结果及条件，说明它回答了什么。实验类型的完整清单可留到正文。
- 有主次时组织成主要发现与补充/边界，避免所有实验各占一句、各自宣布成功。
- 末句承接实际研究所得，不空泛重复“广泛应用潜力”。摘要不能继承范文的数值、证明、硬件或推广承诺。

有些范文的模块式摘要适合完整系统稿，有些集中在一个机制或发现。继承其功能关系并修正明显的冗余、错字和缺乏支持的措辞；不是逐词替换。

## 4. Introduction 建立需要回答的问题

`Problem → Gap → Challenge → Insight → Approach → Contributions` 是漏项检查，不能规定所有引言的段落顺序。原文可能把相关工作内嵌于问题，可能单主贡献连续叙述，也可能先给不同挑战再逐项回应。

为新稿先形成一条可以读通的关系：实际任务/现象为何重要；已有做法在什么条件下不足；这一不足为何难以直接解决；本文利用什么性质或关系解决它；哪项证据检验这个判断。按所选来源展开需要的环节，允许合并，不为齐全而添加空段。

局限必须有范围与来源。既说明已有研究解决了什么，也精确界定当前问题；不要把“不是本稿所研究的问题”改写成“现有方法失败”。贡献按真实推进的结果或机制组织，避免把任务清单包装成多个创新点。引言末段的结果预告、贡献和章节导航各有职责，相邻部分不重复同一内容。

## 5. 方法与公式形成一条解释路线

先读范本的代表性方法段：哪些对象提前定义，何处借用已有骨干，哪一个限制触发新表达，长推导放在正文还是附录。方法章节的顺序由科学依赖决定，不自动等同软件模块清单。

对关键公式写明：**需要形式化的问题/关系 → 已建立的对象与条件 → 公式 → 它允许作出的判断、计算或下一步**。这些内容可跨数句，不要求每条式子都配相同的前后套句。

- 新机制、核心目标、约束和后文反复使用的关系适合单独编号；简短代入或局部定义可用行内式。按来源的节奏与目标格式决定，不凑公式数量。
- 第一次出现的符号就地解释，量纲、范围、依赖和假设保持明确；不用重复全部已知符号来拉长段落。
- 已有方法在第一次借用的位置引用，说明本稿改变的部分；新推导的成立条件和技术贡献归属保持清楚。
- 必要的推导展开到读者能检查；常规代数可压缩，有证据价值的性质/证明保留，长细节按目标格式移至附录。
- 公式是句子或论证的一部分，标点、编号、交叉引用和符号体例按目标模板核对。式后不止解释符号，也交代其作用或后果。

例如 R08 的方法沿旧关联误差、局部时钟问题、时间修正、短时运动假设、新误差、可优化表示展开（PDF pp.2–3，详见其写作卡）。可以迁移“前一步留下的障碍推动下一步”，不能移入它的具体模型。R15 的表达以表征、策略和训练解释为主；没有理由为相似观感增添编号公式。

## 6. 引用服务于判断，格式服务于目标期刊

读所选来源的引用位置及 [EVIDENCE_AND_CITATION_PLAYBOOK.md](EVIDENCE_AND_CITATION_PLAYBOOK.md) 的引用部分。区分主题类别证据、具体技术来源、条件下的局限、采用的方法、baseline和数据来源。

文献组只支撑它们共同支持的命题。具体优缺点放在能支持该判断的来源附近；引用后给出本稿与已有工作的实际关系，避免把文献序列写成同句式流水账。作者名有助于具体归属或比较时保留，不因“去AI味”统一删除叙述式引用。

本稿实际引文另行核验，编号由自己的bibliography生成。IEEE编号、作者—年份和上标引用的来源家族不同；论文逻辑可借鉴，文末格式按目标模板处理，不混合三种体例。不要复制范文的参考文献列表或现成编号。

## 7. 篇章排布与结果解读

全稿保持一个主范本控制阅读路线；局部补充来源只解决明确的缺项。Letter压缩相同目标的解释层，Transactions展开真实新增的模型、性质、系统依赖和能力验证。长度不够时寻找尚未解释的科学内容，不以同义复述扩篇。

结果先回答试验问题，再给支持该判断的比较与数据；有依据时解释机制，同时保留失败、无改善、代价和适用条件。设置与复现信息应齐全，主要结果段不逐格重读表。相关工作、引言、方法、实验和结论沿同一主问题推进，但各自贡献新的信息。

排版对照按页面职责匹配首页、方法页、结果页和文献页；关注段落长度变化、公式之间的解释、图表首次引入位置和正文密度。统计词数或方程密度只是诊断；真实版面由目标模板试排确认。

## 8. 用实际文字验收

选摘要、引言关键转折、机制开篇或核心公式段、主要结果解读中与当前任务相关的单位，与所选范本并排读。只交付局部文字时不要强行完成全稿检查。

- **依存检查**：若相邻句/段可任意交换而不影响理解，检查是否只有并列介绍；复现清单和独立设置说明是合理例外。
- **理由检查**：读者是否知道某个操作为什么需要，以及它依赖什么？不能用无证据的因果补缺。
- **信息增量**：同一主张是否在相邻部分重说，没有新解释或证据？
- **条件与归属**：假设、比较范围、采用/新提出的内容和证据强度是否准确？
- **实际样本**：记录一个真实的改前/改后片段及原因；依据文字是否论证清楚判断，不用文件数量或结构验证代替阅读质量。

修最大的已观察问题，保留原本清楚的文字。风格检查通过不证明论文结论有效；原文、数据或实现有冲突时单独列出科学问题，不能靠改写消除它。
