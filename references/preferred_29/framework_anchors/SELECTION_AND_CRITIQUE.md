# 原图逐项比较、选型与当前试图诊断

这份记录依据逐张查看的 8 张真实裁图，以及 `tmp/reference-forward-test/framework.png` 的第一次 R06 风格试画结果。它是视觉与表达诊断，不是方法有效性评价。不能把“图片已生成”“节点正确”或“静态检查通过”写成“已经与原图几乎一样”。

## 不会每篇都用同一张图

R06-F2 只是第一次跟踪方案试画的主范本，不是所有论文的默认模板。每次按当前方法的真实拓扑、主贡献和图的用途选择具体原图；文章形式及栏宽决定能容纳多少细节，不能单凭“Letter”或“Transactions”决定图型。

一篇文章可能需要系统总览、核心机制、网络结构、训练流程和实验设置等不同图。它们可以采用不同图型，但应统一字体层级、颜色含义、线宽和箭头含义。每张图选择一个主范本，最多一个明确用途的辅助范本。正文主范本与框架图主范本可以不同，须说明为什么这个图更贴近当前机制。

模仿的对象包括原图的视觉秩序、布局比例、信息密度、机制表现和线条语法。不能为填满源图格子而新增算法、重复输入，或把源论文专属的网络层、频率、奖励权重、算法名称搬进新方法。

## 当前 R06 试画图还差在哪里

对照对象为第一次测试图 `tmp/reference-forward-test/framework.png`。以下问题超出“字体、颜色已经匹配”的层面；原来的报告把部分问题标成 MINOR，低估了它们对总体观感的影响。

1. **最像的只是外框，内部机制表达不够。** 原图用扇区、意图分叉、姿态表示、体素地图等各不相同的形式解释步骤。新图反复使用红点、弧线和斜线障碍矩形，“Motion intention estimation”这个关键计算却只有名称。小图数量接近，不等于机制信息密度接近。要让每幅小图回答具体问题：输入是什么、被改变的是什么、输出是什么；缺少机制事实时保留一个明确功能块，减少填充卡片。
2. **源图的格子数绑住了新方案。** EKF target state 和 obstacle map 已经在 Perception 中出现，橙色组又各占一个大卡片。“Motion intention output”是结果信号，却与预测算法同尺寸并列。视觉上把输入、运算、输出都画成同类模块，产生了多出几步算法的错觉。可把重复数据改为紧凑接口标记，把输出放到连线上，留下真正计算模块；仍保留 R06 的分组、配色和机制缩略图语法。
3. **左上的大号符号无人机占了主要空间，却解释的信息少。** 原图同样有大平台区，但实机照片及组件标注提供硬件证据。试图用简化四旋翼图标放大替代照片，空白和线圈占比高；“Symbolic UAV”也属于内部说明。没有实机材料时，应缩小此区，让传感器→控制→观测闭环清楚即可；不能伪造照片补足原图质感。内部稿标记可放在图外。
4. **数据路由可读性不足。** 顶部 self state + obstacle map 和底部 reference trajectory 绕过大片外框，黑色总线、彩色组边框和回路线同时围住图。感知三种输出合成一条线后，读者较难快速确认各约束使用哪些数据。应逐项列出必需接口，再为分支留局部通道、写短标签；不靠一个汇总总线掩盖输入关系。要特别确认地图到避障/可视约束、自状态到优化器、参考轨迹到控制器的真实关系。
5. **视觉重量不够有层级。** 大标题、卡片标题和许多信号标签都很重，黑色粗虚线与色彩虚线叠加；Perception 名称密集，右侧大白色小图又过空。原图也用粗体与虚线，但信息纹理丰富、卡片标题短，而且组标题、机制、接口的职责容易分辨。改稿应保留源图字体语法，同时缩短信号标签、调整标题与数据标注重量、统一内部留白；不能用“全部改成无衬线”假称贴近 R06。
6. **局部示意还可能传达错误几何。** 当前右下优化缩略图的符号 UAV 与下方斜线障碍块重叠；蓝色轨迹从重叠处发出。即使是概念图，也容易被读成 UAV 从障碍中出发。应检查飞行器、轨迹、预测点、扇区、障碍之间的相交及含义；若确实要画遮挡/碰撞示例，必须显式说明其角色。上方预测卡曾修正的一处相交不代表所有小图已经通过几何核验。

这些限制说明首稿只是识别到了 R06 的分区，尚未达到用户要的原图观感。未知意图表示、预测算法和优化内部机制不能靠编造科学细节解决；它们应决定简化程度与下一步所需作者材料。

## 每次选图的实际顺序

1. 用一句话写清本图主问题：系统依赖、策略与优化器接口、训练采样、学习梯度路径、训练/部署差异、硬软联动，或控制职责层级。
2. 画当前方法的真实节点和边，区分输入/运算/输出/约束/环境/执行器；列出哪些机制有实际资料，哪些只有功能级定义。
3. 打开最相关的 2–3 张**真实原图**，比较主贡献是否处于同一视觉位置、支路与反馈是否相近、细节是否在最终栏宽下可读。选一个主范本，写清舍弃另两个的理由。
4. 转移选定原图的比例、层级、图案与线条语法；按新方法真实节点调整卡片数量。颜色应对应当前方法角色，不只按原图坐标涂色。
5. 先检验接口与几何，再与原图逐项并排对照：画面重心、信息密度、字体、机制表现、线条及留白。不能只比颜色、外框或是否存在若干块。
6. 在实际单栏/双栏尺寸查看；分别记录“内容正确”“视觉接近”“仍缺资料”。第一项通过不能替代后两项。

## 图组一致性

同一篇文章统一：文字字号层级、符号定义、模块/数据/约束的表现规则、颜色角色、前向/反馈/梯度线条语义、图注语气。

允许每张图不同：总体横竖比例、面板数量、是否使用照片、是否用网络层形状、是否需要坐标系与曲线、是否显示优化表达式。系统总览不能替代网络结构图，框架图也不能替代真实结果图或实验设置图。

不同文章：重新选型，不能沿用上一稿的 R06 橙蓝绿卡片骨架作为惯性默认值。同一算法家族也要比较主贡献是否发生变化。
