# 从用户范本到新论文：先锁定参照，再生产

适用于给定主题、研究方案、手稿或一张方法图，希望成品接近用户提供的 29 篇论文。入口是范本选择，而不是先套通用 Transactions 大纲或固定浅色框图。这里只约束该用户的模仿任务；内容、数据与可验证主张仍由新项目提供。

## Entry

Use before substantive production for the user's reference-matching requests. For a local task diagnose and map only what can change that output; a title or research plan can start a provisional mapping.

## 1. 选择主范本

读 `references/preferred_29/MANUSCRIPT_STYLE_PLAYBOOK.md`，用 `scripts/select_style_reference.py` 检索候选，随后读候选的逐篇 profile。选择依据按次序为：作者指定 → 文章形态与任务 → 科学机制/信息流 → 实验资源 → 篇幅与视觉密度。标签匹配只是候选，不自动证明适合。

- 全文选一篇主范本控制章节、节奏、版面、图组；必要时选一篇辅助范本填补真实差异，不平均混合 29 篇的风格。
- 框架图单独选一张主图。主图可以与全文范本不同，说明原因；优先沿用主图整套视觉语法，不拼成新风格。
- 每篇重新按科学关系和图的用途选择，参照 `references/preferred_29/framework_anchors/SELECTION_AND_CRITIQUE.md` 的逐图优势。未指定时比较最接近的 2–3 张；之前的 R06 测试图不成为通用模板。八个量化锚点不是完整图型上限，其他原图更合适时查看其 PDF。
- Letter、Transactions、会议稿、单栏预印本和 Nature 版式分开。元数据只证明手中 PDF 的形态；原稿没有明确刊头时，不能仅凭页数宣布其发表类别。
- 题目或方案也可启动：选具体范本，交付有内容的暂定大纲、图形草案和实验计划；分别标明已知事实、设计假设、缺失证据。

## 2. 写入 STYLE_LOCK

填 `templates/REFERENCE_STYLE_CONTRACT.md`，整篇任务将其保存为项目的 `STYLE_LOCK.md`；一张图可直接附在该图规格中。记录以下四层：

1. **论文形态**：主范本 ID、PDF 版本/页码、章节树与节内顺序、各段职责、图表首次出现位置、正文与参考文献的预算。
2. **文字节奏**：摘要的句子职责，Introduction 如何由场景进入挑战，related work 独立还是内嵌，方法如何从总览走到公式，结果如何按问题排列；继续读所选 `writing_moves/` 卡、`PROSE_ARGUMENT_PLAYBOOK.md` 与 `SENTENCE_CRAFT_PLAYBOOK.md`。回到相邻原句，记录句段依存以及主语、谓语、信息次序、条件范围、指代、比较/数字职责、证据强度与引用归属。迁移选择与关系，按本稿事实重建文字，不复制句子或统一所有来源的顺序。
3. **视觉参数**：具体图号与裁图、宽高比、组框与模块的相对位置、留白、字体层级、线型/箭头/图案、颜色关系、子图标记、图注和表格形态。
4. **证据顺序**：范本先测什么、怎样分基线、在哪验证核心机制与边界；逐项写明本稿保留、替换、删去及理由。

规则优先级：用户本次选择与新稿科学事实 → 当前目标期刊的已核验要求 → STYLE_LOCK → 29 篇中的其他案例 → 旧语料一般建议。期刊的证据要求不自动改变参考图配色或构图。

## 3. 产出与比对

全文工作先给出参照驱动的 paper blueprint 和图组，再依据已有材料写作。实验计划先继承范本的证据角色和排列，再补本稿新贡献所需的对照；所有指标、预算、成功定义和统计单位重新落实到本项目。详见 `references/preferred_29/EVIDENCE_AND_CITATION_PLAYBOOK.md`。

框架图先打开 `references/preferred_29/framework_anchors/` 中的**真实裁图**或从原 PDF 指定页渲染。旧 sketches、gallery 示意、自动 captions 都不能替代原图。使用 framework 模块的重画过程。新图在旁并排显示主范本，按实际刊载宽度检查。源图是视觉学习材料，成品要有本稿的真实文字、节点和路径。

先写每张图要回答的问题，再决定是总览、机制、网络、训练/部署还是实验图。同篇统一术语、字体层级、线宽、变量颜色和图注；不同用途允许不同构图。源图多出的运算槽位删除或合并，不靠重复状态/地图或新增无依据算法凑数。机制小图各自解释具体关系，主创新需要相应视觉展开，无法从作者材料展开时如实标注暂定粒度。

排版检查需要渲染稿件：以全文范本相同的页面形态观察首页、中间方法页、实验页、参考文献页；不要只比较 Markdown。独立 LaTeX 文件遵从当前环境的原生编辑器/编译器；多文件项目用项目已有的编译方式。不得为展示风格虚构论文结果。

尚未有完整稿件的真实项目，可先完成引言、问题定义与方法、核心图组和图注的试排，再与来源中承担相同职责的页面比较。结果缺失时写清实验设计，不造 Results。按 `audits/WRITING_STYLE_AUDIT.md` 与 `audits/FIGURE_TABLE_AUDIT.md` 查看段落职责、公式解释、图组占位、首次引用和图注；不是再生成一张孤立框架就完成全文风格验证。Letter 和 Transactions 用各自匹配的实际贡献检验，不把一份短稿机械拉长来模拟长文。

有真实实验材料后，选择决定主贡献是否成立的一组公平对照，跑通原始日志→聚合与图表→图注→结果段落的来源链；指标、统计单位、失败定义与条件保持一致。新稿实际使用的引文再逐条查官方元数据、版本和被引内容。逐篇范本中的引用位置/格式观察不等于新稿引文已核实。

## 4. 验收与有限修正

分别报告科学证据状态与视觉状态。每次真实检查保存对照图与差异，不用“参数齐全”或“校验通过”证明审美质量。

|项目|具体问题|发现偏差后的修正|
|---|---|---|
|文章形态|是否偷偷变成另一种长短文？相关工作和验证是否挤占核心方法？|恢复主范本的层级与预算，保留有科学理由的差异|
|段落节奏|是否每段都变成泛化的背景或宣传？公式前后是否仍有对象、条件、解释？|按逐篇 profile 的职责重写，只用本稿信息|
|图组|是否把每个指标拆图、漏掉关键机制、证据顺序改变？|恢复范本图组功能，补本稿必须的证据|
|框架构图|是否仅有相似配色，层级、图案、路线却全变了？|恢复主图的布局骨架、比例与连接方式；科学差异写进映射|
|排版|字号、图表密度、图注、行宽、参考文献外观是否有明显跳变？|在实际宽度/页面渲染中修正，不能靠缩小文字掩盖|

视觉完成状态依次是 `REFERENCE_SELECTED` → `STYLE_LOCKED` → `DRAFT_RENDERED` → `REFERENCE_COMPARED`。尚未看到新渲染图时最多报告前两项。科学内容仍暂定时，视觉比对合格也只能叫暂定草图。

每轮先修最明显的 2–3 个差异，最多三轮；仍有差距则交付已完成文件与具体剩余问题，不宣称“几乎一样”已被客观证明。独立交接测试在真实项目或必要的验证任务执行，不在普通使用中强迫作者走额外审批流程。

## Exit

Deliver the requested artifact with its source-style mapping and honest rendering/comparison status. Empirical claims remain limited by actual new-project evidence even when the visual match is satisfactory.
