# 02 Research Architecture

## Entry

Require a Project Profile. Use for Modes A, B, G, or when integration reveals a broken scientific argument.

## Build the chain

Record each element as user evidence, verified literature evidence, interpretation, or provisional design:

1. **Scientific question** — a falsifiable question about an object under stated conditions.
2. **Existing limitation** — the specific limitation of the closest relevant approaches.
3. **Research gap** — what knowledge or capability is absent, not merely what technique has not been used.
4. **Technical challenges** — two to four obstacles that prevent a trivial solution.
5. **Core insight** — the principle that makes the proposed direction plausible.
6. **Proposed mechanism** — how components act on the challenges.
7. **Expected effects** — mechanism-level consequences, not unverified performance numbers.
8. **Evidence required** — proof, experiment, comparison, stress test, runtime, or physical validation needed for each effect.

## Stress tests

- Remove the proposed mechanism: does the gap remain identifiable?
- Exchange the method name for a generic technique: does the claimed novelty disappear? If not, the gap may be technique-led rather than scientific.
- Trace each limitation to a mechanism; delete limitations the paper does not answer.
- State the conditions under which the insight may fail.
- Separate scientific significance from application attractiveness.

## Gate

Require a complete `Problem → Gap → Challenge → Mechanism → Claim → Evidence` chain before full-paper drafting. If inputs are incomplete, label the architecture `PROVISIONAL`, identify the smallest author decision or experiment that can resolve it, and stop downstream claims from becoming factual prose.

## Exit

Produce an architecture brief with traceable links to the Contribution Matrix and Claim–Evidence Matrix.
