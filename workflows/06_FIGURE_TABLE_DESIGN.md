# 06 Figure/Table Design

## Entry

Require claims and an evidence plan. Use for Mode F or before a full Paper Blueprint.

## Procedure

1. Copy `templates/FIGURE_TABLE_PLAN.md`.
2. For each asset, state its scientific question, evidence role, related claim/contribution, section, data source, preferred format, and caption function.
3. Ask: “What does this asset prove?” and “What is lost if it is removed?”
4. Remove, merge, or demote assets without a distinct answer.
5. Sequence assets along the argument, such as problem/setup → architecture → mechanism → main comparison → analysis/stress test → real-world evidence, while adapting to paper type.
6. Route visual exemplars for the current asset type; do not copy their graphic composition or wording.

## Format decisions

- Use figures for spatial, temporal, architectural, distributional, or qualitative relationships.
- Use tables for exact multi-method/multi-metric values, configurations, and compact comparisons.
- Avoid tables that duplicate plots and plots that merely decorate a few exact values.
- Plan captions to state context, encoding, comparison, and the intended reading; keep interpretation in the text.
- Mark column span, typography, and panel count as design decisions, not corpus-derived mandates.

## Integrity

Do not create a graph before defining the experiment and evidence need. Do not imply unavailable error bars, significance, hardware, or scenarios. Mark missing data `MISSING_INPUT`.

## Exit

Every planned asset has a unique evidence role, a real data dependency, a section home, and a nonredundant caption function.
