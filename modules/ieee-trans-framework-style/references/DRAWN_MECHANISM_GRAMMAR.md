## 3. 从科学关系写成可执行画面

设计顺序：**对象 → 操作或前后状态 → 空间关系 → 图画 → 短标签**。先决定图里发生什么，再命名模块。按当前方法需要选取关系，不为凑满源图格子新增对象或阶段。

计算对象也可为实际张量、样本、表示或策略；关系可为采样、聚合、反馈和参数更新。计算框架不必改画成物理场景；去文字检查检验结构与操作是否可见，不要求不用符号就辨认具体损失。

给绘制 agent 的每个核心机制说明至少交代：

- **对象与依据**：实际路径、控制点、障碍边界、候选目标或状态等；分别从何处得到。示意与数据轨迹明确区分。
- **变化**：哪个量保持不变，哪个量改变；可见的前后状态如何对应。无前后过程时直接表达真实约束或交互，不能编造优化迭代。
- **关系与视角**：相邻、对应、接触、穿过、投影、包围或位移中的哪一种；读者从什么视角看清它。二维足够时保留二维。
- **描画顺序**：背景参照 → 次要对象 → 核心对象/变化 → 必要连接 → 短标签。具体规定线、点、面分别代表什么，避免只写“更立体”“更精致”。
- **省略内容**：求解器名称、完整公式与阈值哪些放在短标签、图注或正文；不要让说明文字挤占机制画面。

### P01 的可执行例子，受当前材料约束

这些是画面设计指令，不是追加研究内容，也不是固定三块布局：

- **Geometry**：同一二维场景中画参考路径与偏移路径；在实际样条坐标位置画控制点，画从参考点到偏移点的位移箭头。共享端点、真实障碍及膨胀边界。改变的是路径几何，不把控制点误称执行时刻；完整样条公式移到图注或正文。
- **Timing**：用两幅严格相同的空间路径表达不同参数律，在共同的等物理时刻标出对应状态点，以疏密变化表现时序作用；点来自当前参数化或明确标为机制示意。箭头或短刻度标明时间顺序。不得把 `c=0` 写成匀速运动，也不得任意挪点制造差别。
- **Observer**：同一个实际查询状态连向真实候选目标，画出候选续接轨迹与末端关系；只有状态定义包含速度时才画速度箭头。候选代价与目标信念的关联可接短标签或小型条形表示；没有数值就不虚构条高。不能用视锥替代计算观察者，也不加无人机传感器。

其他研究应从自己的对象和操作建立画面；不能机械复制这三个例子。局部透视、遮挡、半透明区域、叠层只有在表达真实关系时采用；它们不能暗示新地图、测量、概率范围或重复实验。

## 4. 观感验收

并排打开所选真实源图与新图，按最终刊载宽度检查：

1. 暂时忽略或隐藏文字后，是否仍能辨认核心对象、主要操作和关系？若只剩框、装饰曲线和空箭头，机制图没有完成。
2. 前后状态是否可对应，变化是否落在对象上？没有前后过程的图是否直接展示其真实约束/交互？不能靠标签才知道“优化”“变形”发生在哪里。
3. 透明面、叠层和线型分别有什么科学含义，是否造成错误的遮挡、碰撞或时间暗示？对象与连接是否有主次，而非所有线框同等突出？
4. 记录源图保留了哪些表达、当前仍有哪些差距；看图结果只可标为“已比较/已修正”。文件生成、脚本通过和 agent 自评分都不能代替观感。只有用户实际确认后才记录作者满意。
