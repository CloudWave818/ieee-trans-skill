# 参照原图重画框架

用户的目标是框架图具有所给论文的观感。先锁定具体原图再绘制，不先发明风格。科学内容来自当前研究；视觉构图尽量保持所选范本。这里的建议是该用户的设计偏好，不是 IEEE 官方格式要求。

## 1. 选择并看到原图

作为主 skill 的子模块时，先读 `../../workflows/13_REFERENCE_MATCHED_PRODUCTION.md`。检索 `../../references/preferred_29/framework_anchors/INDEX.md` 和 `../../references/preferred_29/cases.json`；选一张机制拓扑与任务相近的主范本，必要时再选一张局部参照。

- 用户指定图片/论文/图号时，优先照它的布局与风格。
- 未指定时，使用 `../../scripts/select_style_reference.py` 查候选，然后打开真实裁图及正文页。检索结果只供选择；不能用卡片描述代替看图。
- `assets/reference-framework-style.jpg` 仍是用户历史提供的一张可选原始风格锚点，**不覆盖**这次选定的 29 篇原图。只有其构图确实适合时使用，不强迫所有框架都有横向 3–5 组、虚线框、衬线字或同套颜色。
- `sketches/`、旧 gallery 预览只是草图，不是原图。原图无法读取时明确说明依据的是历史笔记；可交付暂定图，不能声称做过原图比对。

选择要匹配实际关系：串行预测→优化选串行原图；训练/部署分离选双路径原图；控制系统选闭环/软硬件结构；几何约束可选机制小图而非硬塞网络图。没有完全同构的图也先选最近的视觉骨架，按科学必需做最少改动，并记下原因。只有内容结构确实不能由现有范本表达时才改造布局，不能因为“更好看”自行换风格。

读 `../../references/preferred_29/framework_anchors/SELECTION_AND_CRITIQUE.md` 的逐图优势与适配边界。候选须回答：这张图的首要任务是什么、它突出哪个机制、当前方法是否真的具有对应关系？一般接口总览可用 R01；几何预测/约束展开可用 R06；高层学习调节底层规划可用 R12；训练分布/奖励闭环可用 R20；域对抗及梯度可用 R23；非对称训练与部署可用 R25；软硬件或功能分层可用 R29。它们是有条件的原型，不是必须八选一；其他范本更合适时打开其 PDF 原图。

未指定原图且候选有明显差别时，在工作记录中比较最接近的 2–3 张：逐项核对核心运算、接口、分支、创新位置与刊载宽度，说明选中理由及其他候选为何较弱。只因都画无人机、都用浅色或都有虚线框不能决定主范本。一次测试用过 R06 不赋予它默认地位；本项目生成的测试图也不能成为后续论文的原始参照。

## 2. 提炼新稿节点与接口

从提供材料建立节点、边与未确认项，记录：对象/操作、输入输出、单位和坐标系、训练或执行阶段、必要分支/重复/反馈、创新展开位置、内容依据。

题目或研究方案可产生 `PROVISIONAL_FROM_TITLE` 或 `PROVISIONAL_FROM_PLAN` 草图，设计假设与事实分开。未知具体算法用中性功能名称，不自行加 Transformer、GRU、actor–critic、QP、CBF 或梯度分支。图里每根关键箭头都应连接真实的输出与输入。

保留用户术语。训练特权输入不能流入部署，策略动作不能悄悄变成电机指令；需要转换接口时展开实际转换。只有真实重复运算才能用层叠、`×N`。

## 3. 锁定视觉映射

使用 `../../templates/REFERENCE_STYLE_CONTRACT.md` 的图形部分，也可继续用 `templates/FRAMEWORK_SPEC.md` 保存节点/边。记录原图、页码、裁图、查看状态和下面的映射：

|要素|需要迁移的原图特征|新图的修改边界|
|---|---|---|
|画幅与比例|宽高比、单双栏、主要区域占比、上下/左右关系、留白|核心分支变化时调整占比，不能任意拉成新画幅|
|层级|外容器、内部模块、图像/网络/几何小图的层数和密度|替换内容及数量，不增加无依据的层级|
|模块图案|源图如何表达感知、编码、优化、动力学与输出|用本稿相关图案重画；避免所有模块退化成同形文字框|
|字体|源图衬线或无衬线、标题/标签/变量层级、行数|长标签先改措辞或局部排布，不靠全图缩字|
|配色|源图功能组的颜色关系、背景与轮廓、强调色位置|新稿重新赋予颜色含义；精确采样与近似建议区分|
|连接|前向/反向/反馈的路径、端口、折线、箭头大小与线型|真实拓扑控制依赖，视觉路线尽量沿用|
|说明|源图面板字母、图例、图注位置|图注默认独立，不烘焙整段正文进图|

一张主图保持同一套字形、边框、图案与箭头语法。不得混入网页卡片、粗阴影、巨大标题、霓虹渐变等参照图没有的元素。源图是什么样就往那个方向重画，不将通用“浅色+虚线框”当成相似性的充分条件。

**迁移的是表达方式，模块数量由本稿控制。** 源图的七个运算槽位并不要求新图有七个框；输入数据、算法运算、输出信号与约束需分别标识。删除没有对应运算的槽位，重排剩余模块，保持原图的区域关系、配色和图案语法。不得重复画感知结果来填空、把中间输出伪装成新增算法，或直接套用范本内部特有的可达域/网络/求解器。

每个机制小图写一句“读者由此看懂什么”。无法说出具体作用时，删去或重画。状态估计应表达观测到状态的关系，地图应表达空间表示，预测应表达当前到未来的关系，约束应表达可行/不可行关系，优化应表达目标轨迹与参考轨迹的关系；不能全部用同一个红点加弧线代替。仅在作者材料支持时展开候选集、损失、网络与公式。主创新不应只有两行文字，配角却占据最大画面。

需要局部机制画法时，按科学作用检索 `../../references/preferred_29/mechanism_patterns/INDEX.md`，打开对应的真实原图局部，并回到其整图确认上下文。优先选择主范本内的画法；若局部借鉴其他论文，在主图字体、线宽、配色与箭头语法下重画。原图裁片仅供学习，不贴进本稿充当新方法或实验素材。输入场景的插画只能说明输入；放在算法框中仍不等于解释了算法。缺少内部机制时明确保持功能总览粒度。

## 4. 绘制

材料足以支持当前粒度时直接生成实际图，沿用当前项目的绘制工具。需要投稿可编辑版本时，优先 SVG/TikZ/已有矢量工程，并渲染预览；节点、文字、路径应可编辑。若用图像生成工具，必须附真实主范本图片及完成的内容映射，明确要求保持其布局与视觉语法；按真实能力交付栅格图，不称其可编辑矢量。

不要把原论文框架改几个标签当成新稿机制；不要把其照片、曲线、实机结果当成本项目证据。布局与图案可以贴近地模仿，网络内容与数据必须重建。实际照片缺失用符号示意并标明，示意不是实飞证明。

## 5. 并排比较与修正

打开主范本原图和新渲染图，以接近最终刊载尺寸比较。按 `STYLE_LOCK` 检查：

1. 第一眼的主链、区域占比、层级、密度是否接近？只配色相似不通过。
2. 内部是否保留源图的机制图案表达，还是被一串文字盒替代？
3. 字体、标签层级、线宽、箭头尖端、圆角、留白是否明显偏离？
4. 所有真实节点、接口、训练执行边界是否正确，线是否穿字/产生歧义？
   同时检查机制小图的局部关系：障碍、可行路径、视线、候选/选中状态不能出现无意的相交或暗示错误性质；结果卡与运算卡明确区分，不为了填满源图的卡片数新增算法。
5. 目标宽度下是否清晰，无裁切、拥挤和错字？原图微小标签不是继续缩字的理由。

另做一次“去色检查”：暂时忽略配色，比较主链、科学解释力、操作/信号区分及层级是否仍接近原图。若只有圆角和颜色像，审美匹配未完成。字号和线宽按最终毫米宽度核对；不是 SVG 像素值看起来接近就算一致。指出最大的实际差距，不自行用分数、脚本通过或文件数量替代原图与新图的人工比较。

保存对照与差异清单，优先修最大的偏差。需要量化时可用源图宽高比与归一化框位置衡量布局偏移，但不能用像素相似度代替科学正确性或审美判断。最多三轮修正后仍有差距，如实列出；只有查看新图和主图后才标 `REFERENCE_COMPARED`。

## 6. 交付

给实际图、真实可用的源文件及简短说明：主范本是什么，保留了哪些视觉特征，哪些科学差异导致布局改变，未确认项在哪里。用户只要图时减少文字。

只修改 skill 时交付 skill 与实际原图锚点即可，不为展示能力发明研究方法。规划、渲染、视觉比对和真实作者验证是不同完成状态。

整篇论文先安排每张图的任务：系统总览、核心机制、网络结构、训练/部署、实验设置或结果。它们可以采用不同构图；同一论文统一术语、字体层级、线宽、变量颜色与图注规则。不要把每张图画成主框架的缩小版，也不要要求每篇论文具有所有图型。Letter 根据核心论点合并图，长文按科学信息量展开。
