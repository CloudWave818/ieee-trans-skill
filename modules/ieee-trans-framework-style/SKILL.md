# 论文／文字 → 参考风格方法框架图

## 1. 任务与触发

用户提供论文、方法章节、算法步骤或一段研究描述，并希望制作方法框架图、网络结构图、系统架构图或算法总览图时，启用本 Skill。

目标不是“把文字塞进几个彩色框”，而是：

**理解方法 → 提炼主链与关键机制 → 建立准确的节点与连线 → 用参考图的视觉语言绘制。**

科学内容由当前输入决定；视觉风格由本 Skill 决定。只迁移构图、配色关系、层级、图形表达与连线语法，不迁移参考图中的具体模型。

本 Skill 可作为 `ieee-trans-skills` 的“方法框架图”子模块。它不覆盖论文数据图、研究动机图、实物实验图或其他图类的既有规范。这里的尺寸、字体和线宽是本 Skill 的设计建议，不是对 IEEE 官方强制要求的陈述。

## 2. 风格锚点：先看参考图

视觉锚点为 `assets/reference-framework-style.jpg`。可访问图片时先看原图；不可访问时按下面的完整规范工作，不声称已经看过图片。

这张参考图值得复用的不是 Transformer、GRU 或 Actor–Critic，而是以下构图逻辑：

- **主链横向展开。** 大阶段从左向右，内部子步骤通常从上向下，主次阅读方向明确。
- **功能分区而非大卡片列表。** 大组采用浅色底、细深色虚线边界；组标题放在边界上方。输入组可拆成上下两个来源框。
- **三层信息层级。** 第一层是方法阶段，第二层是真实子模块，第三层是局部运算、特征、数据或输出形态。
- **模块内部有图形内容。** 输入小图、关系图、token 条、层叠块、递推路径或分布示意承担解释作用，不是装饰。
- **紧凑、平整、克制。** 白色画布、低饱和浅色填充、细轮廓、小幅圆角、衬线字体；整体像论文插图，不像演示文稿、网页面板或商业信息图。
- **连线表达真实接口。** 箭头让读者知道信息从何处产生、经过何种运算、变成什么输出。

不要把后来生成的通用示例图当作科学依据。参考图片本身也只提供视觉依据，其箭头和模块关系不能替代当前论文的定义。

## 3. 输入处理：论文或一段文字都能启动

### 3.1 完整论文或方法章节

读取与方法有关的正文、公式、算法、实现说明和现有图；不能只凭摘要决定内部结构。优先使用正文明确说明的模块、变量和接口。正文、公式与旧图矛盾时标出冲突，不自行选择更好看的连接。

记录支撑主要节点和重要连线的来源位置，例如小节、公式、算法步骤或输入文字中的句子。来源表是工作材料，不必放进图片。

### 3.2 普通文字或简要方法描述

直接从文字提炼可确认的输入、操作、输出和依赖。文字只支持粗粒度流程时，就画粗粒度框架，并用有依据的局部图形增强表达；不为了做出“复杂网络感”补入注意力、MLP、GRU、优化器或损失函数。

非关键未知信息在图外简短说明。确实会改变主结构、又无法用较粗抽象表达的未知信息，才提出最少的澄清问题。不得要求用户先自行整理成完整框架才能开始。

### 3.3 只有题目或研究想法

可先输出明确标注为 `PROVISIONAL` 的概念框架，只表达已有依据的关系。设计假设、建议机制与作者已实现内容必须区分；不得把建议稿称为论文最终方法架构。

## 4. 内容提炼：先回答这些问题

内部建立一份简洁的 `METHOD_FACTS`，至少回答：

| 字段 | 要提炼的内容 |
|---|---|
| 核心目的 | 方法要完成什么任务，解决什么具体困难？ |
| 输入 | 方法真正使用哪些观测、状态、历史、几何、任务或约束？ |
| 表示／预处理 | 输入经过怎样的编码、构图、估计、信念更新或坐标变换？不存在则不强设。 |
| 核心机制 | 论文区别于普通流程的运算、约束、学习或决策发生在哪里？ |
| 输出 | 输出是预测、信念、候选轨迹、参考路径、动作、控制指令还是其他对象？ |
| 主数据流 | 每个输出具体进入哪个后续模块？ |
| 分支与回路 | 哪些是并行分支、条件选择、时间递推、闭环反馈、训练更新或参数共享？ |
| 贡献位置 | 最应让读者看清的 1–3 处变化是什么？ |
| 证据与未知 | 哪些信息有原文支持，哪些尚未说明？ |

将方法压缩为一句“方法主线”：

> 以【真实输入】为起点，经【真实表示／处理】和【核心机制】，得到【真实输出】，用于【任务目的】。

这句话用于决定全图顺序，不意味着所有方法必须拥有这四种阶段。

### 4.1 抽象到合适粒度

默认尝试 3–5 个一级功能组；以科学内容和可读性为准，不固定为四栏。完整图特别复杂时先保留一条主链，将训练细节或局部机制拆到伴随图。

一级组名称应说明功能，如观测表示、交互建模、候选评估、轨迹求解、决策执行；不能统一改成无信息的 Input / Process / Output。

二级节点说明关键运算。三级内容用局部图形解释输入形态、变量关系或输出形态。并非每个节点都需要第三级。

只有顺序依赖才画为串行；并行模块放成分支；条件触发使用有条件标签的路由；不存在时间递推就不添加回环。

### 4.2 按方法类型适配，而非套网络模板

以下只是组织思路，只有被输入内容支持的部分才可出现：

- 学习方法可围绕观测、表征、交互／时序建模、策略／预测输出组织。
- 规划与优化方法可围绕实例、决策变量、候选／约束／求解、可执行结果组织。
- 估计与决策方法可围绕观测、状态／信念更新、预测／评估、决策组织。
- 系统方法可围绕感知、估计、规划、控制组织，并显式表示真实闭环。

没有神经网络的论文也采用同一视觉语言，但不出现伪造的神经网络部件。

## 5. 建立节点—连线契约

绘图前使用 `templates/FRAMEWORK_SPEC.md`，至少建立节点表和连线表。

每个节点记录：`ID / 标签 / 真实作用 / 输入 / 输出 / 所属组 / 来源 / 图形表达`。

每条重要边记录：`起点端口 / 终点端口 / 传递对象 / 边类型 / 来源`。

必须满足：

1. 数据边连接真实产物及其使用者，不能仅因为两个框相邻就连线。
2. 不将执行期数据流、递推状态、训练梯度和文字关联混成同一种箭头。
3. 不把训练／价值／损失支路自动接到在线动作输出；只有原文明确定义的数据依赖才允许这样连接。
4. 时间状态的时刻与方向一致；残差路径、门控、共享参数和重复次数均需有依据。
5. 多输入组合有明确合流位置。加法、拼接、门控不能一律用未定义圆圈表示；有依据时标明 `+`、`Concat` 或对应算子。
6. 动作、参考量和底层控制指令不能互相偷换。原文给出的单位、坐标系、维度和时间索引保持准确；未给出的不杜撰。
7. 条件分支、反馈和外部约束只在原文支持时出现。约束不是“有一个框”就算表达清楚，要说明其作用于哪一步。

## 6. 视觉规范：必须画出参考图的感觉

### 6.1 画布与总体比例

白色背景。优先紧凑横向构图，图主体宽高比可从约 `2.6:1–3.2:1` 开始试排；这不是固定比例，内容复杂时调整。

默认先按双栏约 180 mm 宽设计，再按目标稿件实际版心检查。单栏版本必须重新排布或拆分，不直接缩小密集双栏图。

核心机制区可略宽于其他组。四组布局可用 `16:25:32:27` 作为不含组间距的初始宽度比例，随后按内容修改。不要强制等宽，也不要无意义地增加宽阔留白。

组标题顶端对齐；大组外框尽量形成整齐的上下基线。输入的多来源小框可以上下叠放。主链左→右，组内以顶部→底部为主；少量回路从外围绕行。

不额外加巨大的总标题、品牌栏、装饰性编号、结论卡片或空白页脚。默认不在图像中烘焙 `Fig. X` 和整段图注，图注单独交付。

### 6.2 三级容器

**一级：功能组。** 浅色大底区、细黑／深灰虚线外框，矩形或极小圆角。标题在框上方，黑色加粗衬线字。不能画成厚重、高阴影的大卡片。

**二级：真实子模块。** 细实线轮廓、适度圆角、浅色填充；同类操作的样式一致。模块宽度与对齐尽量统一，但不得因统一形状掩盖不同层级。

**三级：局部数据与机制。** 输入图标、特征条、节点关系、token、候选轨迹、信念条、分布或小几何示意。大小从属于主结构，细节仅保留解释本方法必需的部分。

层叠框或 `×N` 仅表示真实重复结构。装饰性的层叠、悬浮卡片和没有端点含义的回绕线禁用。

### 6.3 配色

下表为迁移参考图视觉关系的建议近似色，不是从原图源文件提取的精确色值。

| 用途 | 建议色 | 使用方式 |
|---|---|---|
| 输入／环境组 | `#F0F0F0` | 浅灰大区底色 |
| 表示／预处理组 | `#FBE5DC` | 浅桃色大区底色 |
| 核心建模／求解组 | `#E8F0F6` | 浅蓝灰大区底色 |
| 决策／输出组 | `#FFF3CC` | 浅奶黄色大区底色 |
| 一类基础运算 | `#E2EFD9` | 淡绿子模块 |
| 另一类基础运算 | `#DCE7F2` | 淡蓝子模块 |
| 递推／门控或另一真实操作 | `#F9E1D4` | 浅桃子模块 |
| 一类特征／编码 | `#E8A6AE` | 柔和粉色小块 |
| 另一类特征／编码 | `#DDBDDD` | 柔和淡紫小块 |
| 文字、轮廓与主箭头 | `#222222` | 深灰，必要时纯黑 |

不要求所有颜色同时使用。大区色用于阶段分组，小模块色用于操作类别，二者的语义层级须清楚。同一篇论文内的既有颜色约定优先保持一致。

颜色的对象含义必须依据本稿重新定义；不能把“粉色=位置编码”等参考图含义强套到其他方法。重要区别同时用文字、形状或明确的线型区分，不只靠颜色。

禁止霓虹色、大面积高饱和色、深色背景、渐变大底、发光描边与明显投影。局部科学示意确实需要连续色带时允许使用，但不得借此制造未经验证的数据。

### 6.4 字体与标签

图内默认简洁英文，说明与工作记录可用中文；用户指定其他语言时遵从。变量与稿件一致，数学字母使用合适的数学排版。

优先 Times New Roman 或相近衬线字体。不是将所有文字加粗：组标题加粗，模块标签常规，变量按数学语义处理。

按最终刊载尺寸试用：组标题约 10–11 pt，模块标签约 8–9 pt，辅助标签约 7–8 pt。尽量维持至少 7.5 pt 的普通标签；空间不足先删冗余或重排，而不是继续缩小。目标模板有更严格要求时服从模板。

盒内标签通常控制为 1–4 个英文词，必要时分两行。段落说明、完整损失函数、长超参数列表和训练配置放正文或图注，不塞进模块。

同层级字号一致，文本居中或按统一规则对齐。不混用多个无关字体，不让文字压边、穿过箭头或覆盖小图。

### 6.5 线条、箭头与端口

以下为最终物理尺寸下的起始设置：外组框约 0.6–0.8 pt，子模块边框约 0.6–0.8 pt，主数据流约 0.8–1.0 pt。箭头尖端小而清楚，节点圆角克制。

主箭头黑／深灰实线，优先短直线和正交折线。连线在框边端口起止，不从文字中心穿过。跨组主链的出口与入口尽量同高。

一级组的虚线表示分组边界，不默认表示不确定性。确需训练虚线或其他边类型时，用清楚的箭头／标签／图例区分，不能让相同虚线样式承担多个不明含义。

反馈回路沿外侧预留通道；交叉优先重排消除。若仍有交叉，必须让相交与相连的区别明确。关键跨组信号可标变量或简短对象名，无需给每根短箭头加冗余标签。

### 6.6 将内容变成小型图形，而非添加贴纸

| 论文确实包含的内容 | 可采用的局部图形 |
|---|---|
| 机器人／无人机／环境输入 | 小型一致的机器人图标、障碍物、目标点或简洁场景示意 |
| 图结构／交互关系 | 小型节点—边关系图 |
| 多来源状态或特征 | 紧凑向量条、分组小块或标注特征条 |
| 编码与 token 序列 | 短列状 token、叠置条块、明确的合并位置 |
| 时间递推 | 真实历史输入、当前状态输出与有依据的递推边 |
| 多假设／信念 | 分支轨迹、概率条或明确标为示意的分布 |
| 候选生成与筛选 | 少量候选曲线与选中／剔除状态 |
| 几何与约束 | 局部可行域、边界、障碍或受约束的轨迹示意 |
| 轨迹／动作输出 | 路径小图、向量、参考量或真实类型的指令块 |

出现 token、GRU、attention、Gaussian、MLP、损失反传、优化器或 `×N` 前，先检查论文是否真的包含相应内容。

示意概率、示意曲线不可装成实测结果；需要时标明 `Schematic`。不编造训练曲线、统计数字或实物照片。小型机器人图标不代表物理实验验证；同一对象的外形、旋翼数与相机位置保持一致。

## 7. 生成步骤与交付

### 步骤 A：理解并提炼

读取输入，建立 `METHOD_FACTS`，形成一句方法主线。记录真实节点、边、贡献与缺失项。

### 步骤 B：结构草案

决定 3–5 个或其他合理数量的一级组；为关键组展开必要内部机制。建立节点与连线契约，检查“输入—运算—输出”是否闭合。

### 步骤 C：视觉映射

对每个节点明确采用框、局部几何、关系图、特征条还是输出示意；分配容器层级、颜色、标签、位置与端口。选用参考图的紧凑横向构图，不照抄参考网络。

### 步骤 D：实际绘制

信息足以支持当前粒度的框架时直接绘制，不反复要求用户确认是否开始。

- 环境提供图像生成工具时，用参考图和已完成的结构规格生成新图。`templates/IMAGE_PROMPT_TEMPLATE.md` 提供通用提示骨架；提交绘图前必须用当前方法的真实内容填写完毕。
- 环境支持矢量绘图时，可构建 SVG 等可编辑源并渲染预览。根据用户的编辑需求选择交付形式。
- 只有文字输出能力时，交付已填实的图形规格与完整绘图提示，并明确尚未生成图片；不能用一句“图已生成”代替实际文件。

AI 生成的栅格图只按栅格预览交付，不能仅更换扩展名或嵌入一张位图就声称获得可编辑矢量图。需要投稿矢量版本时，应重建文字、节点与路径，并核对重建前后的科学关系。

### 步骤 E：科学与视觉复核

实际查看渲染结果，按第 8 节验收。只有看到实际渲染图才能声称已做视觉检查；规格完整不等于渲染合格。任何无法核验的部分如实标记。

### 默认交付顺序

1. 简短说明从输入提炼出的主链与核心机制，必要时列出关键未确认点。
2. 提供实际框架图；用户只要图片时尽量减少文字。
3. 按实际能力和请求附源文件、绘图规格或单独的图注，不宣称并未产出的文件。

处理本 Skill 的创建／修改请求时，交付 Skill 本身即可；只有用户提供方法并请求出图时才进入实际绘制，不为了展示 Skill 擅自发明一套方法。

## 8. 验收门槛

### 科学正确性

- [ ] 主链来自当前论文／文字，而非参考图的原始网络。
- [ ] 所有具体算法模块、变量、分支、重复次数与回路均有依据。
- [ ] 每条关键边连接真实输入与输出；没有为了好看添加的依赖。
- [ ] 训练与部署、历史与当前、参考量与控制量没有混淆。
- [ ] 本方法的关键机制在正确位置展开，不只是一个改了名称的黑盒。
- [ ] 未知信息未被悄悄补成既成事实；示意图未冒充实验结果。

### 风格匹配

- [ ] 横向功能分区、浅色底、细虚线外组框、上置组标题清晰可见。
- [ ] 内部是细实线圆角模块，并有内容相关的局部图形。
- [ ] 字体具有参考图的衬线学术感，整体紧凑而不过密。
- [ ] 配色柔和，不像深色科技海报、PPT 卡片流程或商业信息图。
- [ ] 没有长段落塞框、巨大总标题、重阴影或无意义装饰。
